# عقد Bootstrap وConfig

## حدود التركيب

`internal/bootstrap` هو Composition Root. يركب PostgreSQL والمستودعات وخدمات التطبيق ومهايئات المزودين والمصادقة. لا يملك منطق اختيار منتجات أو قرارات مبيعات، ولا يحتفظ باتصالات التجار أو أسرارهم في حاوية عامة.

`BuildAPI` يبني تشغيل HTTP من `ProcessConfig`. و`BuildDependenciesWithRealtime` يركب مستودعات PostgreSQL مع ناشر التحديثات. `APIRuntime.Serve` و`APIRuntime.Shutdown` يديران دورة تشغيل API.

## الإعدادات والأسرار

- إعدادات العملية تخص التشغيل والاتصال بالموارد.
- إعدادات التاجر والسياسات والاتصالات بيانات محكومة بنطاق `business_id` في PostgreSQL.
- الأسرار تُحل عبر SecretStore عند الحاجة؛ لا تدخل DTOs أو سجلات التشغيل.
- لا يدخل SDK خاص بالمزود إلى Domain أو Application؛ الاتصال الخارجي عبر Ports وAdapters.

## مداخل التشغيل

| المدخل | المسؤولية |
|---|---|
| `cmd/api` | تشغيل HTTP |
| `cmd/runtime` | تشغيل المعالجة الخلفية |
| `cmd/migrate` | تطبيق ترحيلات PostgreSQL دون بناء خدمات التطبيق |
| `cmd/openapi-gen` | توليد عقد HTTP من DTOs وتسجيل العمليات |

## المعالجة والإغلاق

HTTP والعمال يستدعون خدمات التطبيق نفسها. Webhook يحفظ الحدث الدائم ويعيد ACK؛ المعالجة اللاحقة تمر عبر العمال. Event Ledger وOutbox وبيانات المحادثة في PostgreSQL، والناقل الخارجي SocialAPI.

عند الإغلاق يتوقف استقبال العمل، ثم تنتهي الأعمال الجارية ضمن مهلة قبل إغلاق مواردها. Liveness وReadiness وصحة المزود مفاهيم منفصلة. لا تنفذ اتصالات الشبكة داخل معاملات PostgreSQL، ولا تعاد محاولة إرسال مجهول النتيجة تلقائيًا.

هذا العقد يصف حدود التنفيذ الحالي؛ تفاصيل التوصيل الفعلية في `internal/bootstrap` ومداخل `cmd`.
