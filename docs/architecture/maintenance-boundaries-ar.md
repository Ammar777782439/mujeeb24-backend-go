# حدود الصيانة ومسؤوليات Mujeeb

**الحالة:** قرار تنظيم للفرع `feat/chatwoot-free` قبل تحسينات السوق اللاحقة. الهدف هو تقليل أثر التغيير ومنع تضخم الدوال، لا زيادة طبقات شكلية.

| الطبقة أو الملف | مسؤوليته الوحيدة | ما لا يفعله |
|---|---|---|
| `automation_rule_services.go` | إدارة قواعد الأتمتة: تحقق الإدخال، create/update/list، وتحويل السجل إلى view | لا يقرأ رسالة واردة ولا يغير محادثة. |
| `automation_execution_service.go` | تطبيق قاعدة مطابقة على حدث وارد وتسجيل تنفيذها idempotently | لا ينشئ أو يعدل قاعدة، ولا يتصل بمزود خارجي. |
| `automation_validation.go` | تطبيع JSON المحدد والتحقق من شروط وأفعال الأتمتة | لا يفتح transaction ولا يصل إلى PostgreSQL. |
| `inbox_services.go` | علامة القراءة والردود الجاهزة وإرسالها عبر عقد Outbox القائم | لا يتولى قواعد الأتمتة. |
| `handlers/*_facades.go` | تحويل HTTP إلى commands/queries، scope، وresponse projection | لا يطبق قواعد أعمال أو SQL. |
| `postgres/*_repositories.go` | حفظ واسترجاع سجلات محددة وعزل tenant | لا يطبق سياسة رد أو اتصال SocialAPI. |

تكون الدالة صغيرة قدر الإمكان: تتحقق من مدخلاتها، تنسق استخدام حالة واحدة، ثم تعيد نتيجة أو خطأ typed. لا تجمع دالة واحدة بين parsing HTTP وقرار أعمال وSQL واستدعاء provider. ويظل المسار الخارجي الوحيد للرسائل هو `OutboundMessage → Outbox → worker → SocialAPI` بعد commit.

## معيار التفكيك

ينشأ ملف جديد عندما تتداخل مسؤوليتان مستقلتان أو يصبح فهم المسار مشروطًا بقراءة أجزاء غير متجاورة. لا يفكك الكود لمجرد خفض عدد الأسطر؛ يجب أن يبقى كل ملف قابلًا للاكتشاف بالاسم واختباره مباشرة.
