# دورة حياة فريق التاجر في Mujeeb 24

## الهدف والحدود

هذه الدورة تجعل **Mujeeb/PostgreSQL** مصدر الحقيقة الوحيد لأعضاء الفريق ودعواتهم وإسناد المحادثات. وهي لا تنشئ دفعًا أو شحنًا، ولا تستعمل Chatwoot. حساب الموظف الجديد لا يُنشأ تلقائيًا ولا عبر تسجيل عام؛ يُنشأ فقط عندما يقدم الموظف توكن دعوة صالحًا ويختار كلمة مروره. لا يملك مزود القناة أو نموذج الذكاء الاصطناعي صلاحية إنشاء عضو أو تغيير دوره أو رؤية رمز دعوة.

| الكيان | مصدر الحقيقة | الغرض |
| --- | --- | --- |
| `principals` | PostgreSQL | هوية حساب المستخدم، بريده وحالته العامة. |
| `business_memberships` | PostgreSQL | علاقة المستخدم بالتاجر، دوره وحالة عضويته. |
| `team_invitations` | PostgreSQL | دعوة مقيدة بتاجر وبريد ودور ووقت انتهاء. تحفظ SHA-256 للرمز فقط. |
| `platform_super_admins` | PostgreSQL | صلاحية منصة منفصلة عن عضوية التاجر، لا تمنح وصولًا صامتًا للمحادثات. |

## الأدوار والصلاحيات

| الدور | إدارة أعضاء الفريق | استلام إسناد محادثة | تنفيذ إسناد محادثة |
| --- | --- | --- | --- |
| `owner` | نعم | نعم | نعم |
| `admin` | نعم | نعم | نعم |
| `manager` | لا | نعم | نعم |
| `agent` | لا | نعم | نعم |
| `analyst` | لا | لا | لا |
| `viewer` | لا | لا | لا |

لا تسمح واجهات إدارة الفريق العادية بإسناد دور `owner` أو نقل الملكية. نقل الملكية يحتاج قرار API مستقلًا، تدقيقًا، وخطوات أمان لا تدخل في هذه الدفعة.

## مسار الدعوة والقبول

> **العقد المعتمد:** لا يوجد تسجيل عام. قبول الدعوة يدعم بريدًا جديدًا أو حسابًا قائمًا، ولا يرسل بريدًا تلقائيًا.

1. ينشئ `owner` أو `admin` دعوة لبريد معيّن واسم عرض ودور غير `owner` وصلاحيات معروفة ومدة لا تتجاوز 30 يومًا؛ الافتراضي 7 أيام. يستطيع `platform_super_admin` تنفيذ العملية عبر API منصة منفصل ومدقق من دون اكتساب عضوية في التاجر.
2. يولّد التطبيق رمزًا عشوائيًا قويًا مرة واحدة. لا يكتب الرمز الخام في قاعدة البيانات أو الـlogs؛ يخزّن `SHA-256(token)` فقط.
3. يتلقى مدير التاجر الرمز في استجابة الإنشاء لمرة واحدة لكي يمرره عبر قناة خارجية يختارها. إرسال البريد أو الإشعار الخارجي ليس جزءًا من V1.
4. يفحص frontend التوكن عبر `POST /auth/invitations/inspect` في body، ولا يضعه في API path أو query string.
5. إذا كان البريد جديدًا، يرسل الموظف الاسم وكلمة المرور مع التوكن إلى `POST /auth/invitations/accept-new-account`. تنشئ معاملة واحدة `principal` ثم `business_membership` ثم تجعل الدعوة `accepted`؛ وأي فشل يعيد العملية كلها.
6. إذا كان البريد موجودًا، يسجل الموظف الدخول ثم يرسل التوكن إلى `/team/invitations/accept`. يتحقق النظام من تطابق بريد الهوية المصادق عليها ولا يغير كلمة المرور أو الاسم العام.
7. الدور والصلاحيات ينتقلان من الدعوة إلى العضوية، وتُطبق الصلاحيات على الخادم من سجل العضوية الحالي.

الدعوة المنتهية أو المقبولة أو الملغاة لا يمكن قبولها. إعادة الإرسال تلغي التوكن المعلق القديم عند الحاجة وتنشئ دعوة وتوكنًا جديدين. لا تعرض استجابات القراءة hash الرمز ولا الرمز الأصلي.

## تغيير الدور والإلغاء

يمكن لـ`owner` أو `admin` تغيير دور وصلاحيات عضو نشط إلى دور غير `owner`، أو إلغاء عضويته. لا يستطيع `admin` منح صلاحية لا يملكها، ولا يمكن منح wildcard عبر Team API. لا تقبل هذه المسارات معرّفات نصية حرة؛ تستخدم `principal_id` بصيغة UUID ضمن `business_id` محلول من JWT. قاعدة PostgreSQL تقفل صفوف الملاك النشطين عند الإلغاء وتمنع تحول التاجر إلى صفر ملاك نشطين.

إلغاء العضوية لا يحذف `principal` ولا يمس عضوياته في تجار آخرين. لن يتمكن عضو ملغى أو معطّل من استلام إسناد جديد، لأن الإسناد يحل عضوية نشطة داخل التاجر نفسه أثناء معاملة تحديث المحادثة.

## الإسناد اليدوي والأتمتة

يستقبل الإسناد اليدوي `assignee_principal_id` فقط. يرفض النظام أي UUID غير صالح، أو عضو غير نشط، أو عضو خارج التاجر، أو دور `analyst/viewer`. يخزّن UUID في حقل المرجع الحالي للمحادثة حفاظًا على توافق المخطط القائم، لا اسمًا حرًا.

تستخدم أتمتة `assign_human` payload المقيد التالي فقط:

```json
{"assignee_principal_id":"00000000-0000-0000-0000-000000000000"}
```

عند فشل الأتمتة بسبب عضو غير صالح، تسجل execution بنتيجة `failed` وسبب معروف، لكن لا تفشل materialization لحدث القناة ولا ترسل رسالة تلقائية. هذه القاعدة تمنع فقدان رسالة العميل بسبب قاعدة أتمتة سيئة.

## مالك المنصة

`platform_super_admin` منفصل عن `business_memberships`. يستطيع إنشاء دعوة موظف لتاجر محدد عبر `/platform/businesses/{business_id}/team/invitations` مع Platform Audit، لكنه لا يتحول إلى عضو ولا يكتسب قراءة المحادثات أو الرد باسم التاجر أو الوصول عبر ScopeProvider.

## نطاق API التالي

واجهات HTTP المنفذة تشمل قائمة الأعضاء والدعوات، الإنشاء والفحص، قبول حساب جديد أو قائم، الإلغاء وإعادة الإصدار، تغيير الدور والصلاحيات، وإلغاء العضوية. OpenAPI يولد من DTOs Huma. قبل commit أو push يلزم تشغيل unit وvet وOpenAPI drift وفحص diff، أما PostgreSQL integration فلا توصف بأنها ناجحة من دون `POSTGRES_TEST_DSN` عامل.
