# قائمة المتابعة في لوحة التاجر

المسار الجديد: `GET /api/v1/businesses/{business_id}/dashboard/follow-ups`.

- يتطلب `dashboard:read` و`sales:read` و`conversations:read`، مع عضوية فعالة ضمن النشاط.
- يعيد أهم خمسة عملاء فقط، وصفًا واحدًا لكل عميل. `has_more` يعني وجود عملاء إضافيين؛ لا يمثل إجماليًا.
- المصدر: فرصة مفتوحة وربط محادثة محفوظ في مصدر الفرصة أو نسبتها. لا تُستبدل المحادثة المفقودة بآخر محادثة عشوائية للعميل.
- يطبّق نفس نطاق قراءة صندوق المحادثات: المشرفون حسب الدور، والموظف حسب الإسناد. تُربط كل الجداول بمعرف النشاط والعميل.
- الرسالة المعروضة هي آخر رسالة عامة واردة من العميل، بحد 600 محرف. لا تظهر الملاحظات الخاصة، ولا تُحوّل درجات الاهتمام إلى احتمالات شراء.
- ترتيب المتابعة: انتظار موظف، طلب ينتظر المراجعة، موعد متابعة مستحق، محادثة غير مسندة، ثم الحالة الفعلية للفرصة.
- تُستبعد الفرص المكتملة والخاسرة والعملاء المؤرشفون. لا تقاطع المحادثات التي يتولاها مجيب أو تنتظر العميل إلا مع مراجعة محفوظة أو موعد متابعة مستحق.
- بيانات الاسم والمنتج والمسؤول والسبب تظل غائبة عند عدم تسجيلها؛ لا تُولد نصوص لإكمال الفراغ.
- الواجهة تبطل القراءة عند تغيير النشاط أو الإسناد وتعيد جلب الحقيقة من المسار؛ أحداث SSE لا تصبح مصدر بيانات بديلًا.

هذا تعديل قراءة فقط. لا ترحيل جديد ولا اتصال بمزود أو نموذج ولا إرسال أو اعتماد تلقائي.

العقد مولد من DTOs في Go عبر `cmd/openapi-gen`، وأنواع الواجهة مولدة من ملف OpenAPI. يجب نشر الباك إند الجديد قبل رفع الواجهة الجديدة.

اختبارات PostgreSQL الأصلية تستلزم `POSTGRES_TEST_DSN`؛ غيابها يعني تخطي اختبارات التكامل، ولا يُعد نجاحًا لها.
