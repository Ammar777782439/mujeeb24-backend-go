# تغطية اقتراحات كتالوج التاجر

التغييرات محصورة في B2B، على `feat/universal-catalog-ai-v3`، دون تعديل البرمبت أو دمج الفروع.

| السيناريو | العقد والتحقق |
|---|---|
| إنشاء عنصر | كل حقول ItemCreate مع عرض واحد على الأقل، وعملة ومصدر سعر واضحين |
| تعديل العنصر | جميع حقول ItemChanges، بما فيها الوصف والأنواع وطرق التسعير والتوفر والتنفيذ |
| خيارات جديدة | أسماء ومراجع محلية فريدة وربط العرض بالمرجع قبل إنشاء IDs |
| خيارات موجودة | IDs من الأدلة، وحالة صحيحة، وحقل تعديل فعلي |
| عرض جديد | مصدر اسم وسعر صحيحان معًا، ومبلغ عشري غير سالب ضمن NUMERIC(20,4) |
| عرض موجود | تعديل amount عبر existing_offers؛ منع IDs المكررة والتعديل بلا حقول |
| أكثر من عرض محتمل | العقد يطلب الاستيضاح بدل افتراض تغيير جميع العروض |
| أرشفة | اسم JSON المعتمد id في Go وOpenAPI وGemini |
| نقص بيانات أو غموض | لا mutation payload قابل للتنفيذ في استجابة غير resolved |
| حقول غير مدعومة | رفضها عند فك JSON بدل إسقاطها بصمت؛ attributes تبقى JSON ديناميكيًا |
| الخصومات والترويج | لا مسار خصم تنفيذي في العقد الحالي؛ عقد المخرج يطلب شرح القصور والاستيضاح بدل إسقاط الطلب |

اختبارات المطابقة تغطي حقول Proposal والإنشاء والتعديل والحذف والخيارات والعروض والحقول الناقصة. القيم المسموحة مأخوذة من CatalogEntityContractDescriptor؛ item_type يبقى نصًا مفتوحًا للقطاعات.

## حدود الإثبات

- الاختبارات المحلية لا تثبت أن النموذج سيحافظ على كل جزء من أي طلب عربي؛ يلزم تحقق حي منفصل.
- لم نضف خصومات أو Promotions أو مخزونًا تنفيذيًا؛ وجود مواصفات JSON لا ينفّذ هذه العمليات.
- الموافقة ترسل proposal_id فقط إلى POST /businesses/{business_id}/merchant-ai/executions. المقترح ونطاقه ونسخ السجلات محفوظة في الباك إند.
- الباك ينفّذ داخل معاملة محلية، ويحفظ النتيجة معها. تكرار الموافقة على المعرف نفسه يعيد النتيجة المحفوظة؛ تغير السجلات منذ المراجعة يرفض التنفيذ.
- EXECUTION_COMMITTED يسجل بعد نجاح المعاملة، وEXECUTION_FAILED عند الفشل. هذه سجلات التنفيذ، وليست سجلات authoring.
- يجب تطبيق الترحيل الجديد 000069 وتشغيل الباك والفرونت المحدثين معًا. المقترحات القديمة دون proposal_id لا تنفذ من الواجهة الجديدة.
- الاختبارات المعزولة تتحقق من مسار الذرية وإعادة التنفيذ؛ إثبات PostgreSQL الحي يتطلب قاعدة اختبار منفصلة.
- اختبارات PostgreSQL تتطلب POSTGRES_TEST_DSN على قاعدة معزولة.
